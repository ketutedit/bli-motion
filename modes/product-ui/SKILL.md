# Product & UI Motion Mode

## Load when

The task involves interface animation, app or website showcases, dashboards, onboarding, micro-interactions, UI transitions, or product demonstrations.

## Think in states and behavior

Identify:

- the product and the user task being demonstrated;
- the initial, loading, active, success, empty, and error states that matter;
- the interaction that causes each state change;
- the primary action and information hierarchy;
- responsive context and target viewport;
- what the interface must communicate about the product.

Do not invent product behavior, data, or controls that the brief or supplied reference does not support. Use clearly labeled illustrative content when realistic data is unavailable.

## Art direction

Balance visual polish with interface clarity. Decide whether the product calls for minimal editorial UI, expressive consumer-app motion, technical dashboard density, dimensional product presentation, or another treatment.

Respect supplied product screenshots, brand assets, typography, component conventions, and layout. Do not replace a real product's identity with a generic SaaS dashboard.

## Motion language

Use motion to communicate state, hierarchy, cause and effect, affordance, and feedback:

- focus and hover states;
- press and release feedback;
- loading and progress;
- panel, modal, and navigation transitions;
- data arrival and chart updates;
- onboarding and feature reveals;
- responsive rearrangement.

Prefer precise timing and restrained overshoot for functional UI. Use more expressive movement for product advertising when it serves the brand. Do not animate every control independently.

## Production and verification

Keep interaction logic separate from decorative motion when possible. Check viewport clipping, text truncation, hit areas, state consistency, reduced-motion needs, and the full transition path. For non-interactive video demos, make the simulated interaction understandable without implying that it is a live interface.

## Quality check

Does the motion explain what the product does? Are state changes understandable? Does the interface remain credible and usable? Is the product identity preserved?
